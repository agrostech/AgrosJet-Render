The user is building a comprehensive, Adisyo-integrated order management system within their existing ShiftJet application.

The core requirements implemented and refined during this session include:
*   **Order Status Management:**
    *   A new Onaylandı (Confirmed) status for when a courier accepts an order.
    *   Admins should be restricted from manually setting certain statuses like Kurye Atandı (Courier Assigned) and Onaylandı (Confirmed), as these should be triggered by specific actions (assigning a courier, courier confirmation).
    *   When an order status is changed to Hazırlanıyor (Preparing) or Hazır (Ready), any existing courier assignment should be automatically removed.
*   **Courier Assignment UI/UX:**
    *   The courier's full name should be visible, without truncation.
    *   The UI for assigning a new courier and re-assigning an existing one should be unified into a single dropdown component.
    *   This dropdown should allow un-assigning the courier.
*   **Preparation Time & Countdown:**
    *   Restaurants must have a configurable preparation time in minutes.
    *   When a new order arrives, a countdown should start based on the restaurant's preparation time.
    *   The Hazırlanıyor status badge should display the remaining time (e.g., 15 Dakika).
    *   When the timer expires, the order status should automatically change to Hazır.
    *   If an admin manually sets an order back to Hazırlanıyor, they should be able to select a new duration (5, 10, 15, 30, 60 mins) from a dropdown submenu.
*   **Order Details & UI:**
    *   The order creation time should be displayed on the far left of each order row.
    *   The payment method should be displayed as text (Nakit, Kart) instead of an icon.
    *   The order details modal should have three tabs: Detaylar (Details), Konum (Location), and Geçmiş (History).
    *   The Konum tab should display a map centered on the delivery address with a 1km zoom, showing both the delivery and restaurant locations.
    *   The Geçmiş tab should show a timeline of all status changes, including who performed the action (admin name, courier name, or Otomatik).
    *   A Target Delivery Time (order time + 35 minutes) and any delay should be displayed below the order creation time.
*   **Map & Visuals:**
    *   The overall map theme should be improved for better aesthetics (e.g., using CartoDB Positron).
    *   Restaurant location markers on the map should be small, round, gray dots.
    *   The default map zoom on the main page should be closer to the company's city.
    *   The height of the couriers list and the main map should be increased.
